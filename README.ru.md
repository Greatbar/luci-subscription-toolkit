# LuCI Subscription Toolkit — v0.2.0 Experimental (0.2.0-r2)

Независимое расширение LuCI для управления подпиской и измерений через VLESS.
Совместимо с **Podkop 0.7.22**; не является официальным продуктом Podkop и не
аффилировано с его авторами. [English](README.md).

Подробности v0.2.0: [политика, бюджеты и история](docs/V0.2.0.md). [Изменения](CHANGELOG.md).

## Возможности

- Основной сервер и порядок резервов по stable IDs; recovery сначала обновляет подписку.
- Минутный мониторинг с общим deadline, опциональное переключение по задержке и защищённый возврат.
- Почасовая история HTTPS-проб и переключений за 24 часа, 7 и 30 дней с ограничением размера и графиками.
- Поддержка дополнительных штатных секций Podkop `Exclusion`.
- Опциональная Proxy/Mixed Proxy-секция `antigravity` с привязкой к stable ID и обновлением при apply/recovery/rollback.
- Очередь планировщика fetch/due с ограниченным ожиданием и мониторинг, устойчивый к скачкам часов.

- Получение кандидата подписки без смены MAIN; отдельное подтверждение применения.
- Стабильные ID узлов, сохранение выбора, проверка кандидата и rollback.
- Сохранение пользовательских доменов и независимых настроек при apply/rollback.
- Конечные задания cron для fetch, health и отложенного применения. Постоянного
  процесса контроллера нет; автоматизация изначально выключена, apply — вручную.
- Массовые проверки HTTPS-задержки, скорости и Telegram Web через один временный
  sing-box. До восьми лёгких проб параллельно; скорость — последовательно без
  фиксированных пауз между серверами. Измерения не переключают MAIN. Полная
  загрузка 4 МиБ быстрее 0,5 с даёт число с отметкой короткой выборки.
- Приватный URL подписки и состояние; публичный RPC не возвращает URL, UUID,
  адреса серверов и ключи. URL вводится в поле пароля и не входит в UCI-очередь LuCI.

## Совместимость

**Experimental: публичный APK ещё не проверен на реальном роутере с официальным
init sing-box.** Указанный ниже профиль совместимости не означает подтверждённую
установку на оборудовании. Ранее профиль проверялся в изолированном OpenWrt-стенде;
последние изменения массовых проверок прошли адресные проверки работоспособности.

Историческое измерение v0.1/r6: все три проверки 11 серверов завершились за **22,7 секунды** на Xiaomi Redmi Router
AX6S с OpenWrt 25.12.5, Podkop 0.7.22 и sing-box 1.14.2. Это результат локальной
установки с другим fingerprint init-скрипта, а не проверки публичного APK.
Совместимость с официальным init на реальном оборудовании пока не подтверждена.

Проверяемый профиль: OpenWrt **25.12.5**, APK, Podkop **0.7.22**, sing-box
**1.14.2** с uTLS/Clash API и официальным OpenWrt procd init-скриптом,
зафиксированным в `root/usr/share/podkop-tools/compat.sha256`.
Нужна одна управляемая секция `main`; дополнительные секции `Exclusion` поддерживаются. Требуются VLESS Selector и runtime `/etc/sing-box/config.json`.
Иные версии и схемы не заявляются. Несовпадение manifest блокирует задания;
не исправляйте его контрольные суммы только для обхода отказа.

Профиль штатных зависимостей сохраняет официальный init-скрипт sing-box;
локальный init FlowPilot не распространяется. v0.2 расширяет политику recovery,
мониторинг и статистику поверх исходной архитектуры r6.
[Подробности профиля](docs/COMPATIBILITY.md).
Текущий официальный feed OpenWrt 25.12.5 содержит sing-box 1.13.21: обычное
`apk add sing-box` не обеспечивает требуемую версию 1.14.2. Подготовьте совместимый
пакет sing-box отдельно; расширение не заменяет бинарник и не обновляет зависимости.

Формат подписки: JSON-массив конфигураций Xray с `remarks` и совместимыми VLESS
outbounds (TCP/gRPC, TLS/Reality; синтетические тесты также используют security=none).
Списки URI/base64, XHTTP и произвольные форматы провайдеров не поддерживаются.
Чужие inbounds, DNS и routing не импортируются.

## Сборка из публичных исходников

Linux x86_64, Python ≥3.12, Node.js ≥20, fakeroot; для Python <3.14 нужен `zstd`.
Все загрузки проверяются по `tools/sources.lock.json`. Сборка APK не требует
роутера, Docker, приватной подписки или доступа к FlowPilot.

```sh
python3 tools/prepare.py
python3 tools/build-podkop-tools.py \
  --apk .build/openwrt-imagebuilder-25.12.5-x86-64.Linux-x86_64/staging_dir/host/bin/apk \
  --output dist
python3 tests/reproducibility.py
```

Получаются `dist/luci-app-subscription-toolkit-0.2.0-r2.apk` и `SHA256SUMS`.
Сборщик нормализует timestamp/права и проверяет root-владельцев. APK не подписан.
Сборка через OpenWrt SDK также доступна: скопируйте этот каталог в
`package/luci-app-subscription-toolkit` и выполните
`make package/luci-app-subscription-toolkit/compile V=s`.

## Установка

Сначала проверьте совместимость и сохраните собственную резервную копию настроек.
Подготовьте перечисленные выше версии Podkop/sing-box и зависимости из `Makefile`.
Старый пакет `luci-app-podkop-tools` и новый пакет совместно не устанавливаются:
они используют общие внутренние файлы. Миграция работающей домашней установки
не является частью этой публикации.

Передайте **собранный вами и проверенный** APK на роутер, затем на роутере:

```sh
apk add --allow-untrusted /tmp/luci-app-subscription-toolkit-0.2.0-r2.apk
```

`--allow-untrusted` нужен для этого неподписанного локального APK. Установка не
получает подписку, не перезапускает MAIN и не включает периодические проверки.
Откройте **Сервисы → Subscription Toolkit: подписка и скорость**.

## Подписка и настройки

На странице «Серверы и подписка» кнопка «Обновить список» перечитывает состояние.
Панель проверок и кнопка «Тест» используют отмеченные тесты; меню «Ещё» запускает
отдельный тест. Одно массовое задание проверяет все принятые серверы или только
активный: лёгкие пробы параллельно, скорость последовательно через тот же sing-box.
«Остановить» прекращает выдачу новых проб и дожидается очистки активных. Перед speed
подтверждается общий лимит трафика. Повторная speed-проба того же ID в течение
60 секунд пропускается с явной отметкой cooldown; между разными серверами
фиксированных пауз нет. Занятый backend явно отклоняет задание. Задержка, скорость
и доступность Telegram Web независимы; устаревание и технические данные доступны
в «Подробностях». Pending-кандидаты этой панелью не проверяются.

1. В настройках введите HTTPS URL подписки. Пустое поле сохраняет прежний URL.
   Redirect и URL с userinfo не допускаются; сертификаты проверяются.
2. Нажмите «Проверить подписку». Fetch проверяет кандидат, но не применяет MAIN.
3. Проверьте изменения и выбранный узел; подтвердите применение конкретной версии.
   Перед apply выполняется повторная загрузка и проверка.
4. Включайте автоматизацию явно. Defaults: fetch каждые 6 часов, health каждые
   15 минут, TTL кандидата 12 часов, отсрочка окна 6 часов, предел серии 24 часа.

Apply с reload может прервать соединения. При исчезновении выбранного узла нужен
проверенный резерв. При отказе всех кандидатов MAIN сохраняется, автоматического
DIRECT fallback для PROXY нет. Восстановление начинается после двух разнесённых
неуспешных health-проб; между попытками — минимум 30 минут.

Подписка хранится в `/etc/config/podkop_tools_subscription` (0600), настройки —
`/etc/config/podkop_tools`, принятое состояние/кандидат/rollback — `/etc/podkop-tools`
(0700/0600). Эти файлы и резервные копии содержат секреты: не прикладывайте их к issue.

## Обновления и диагностика

Расширение не выполняет `apk update/upgrade`, не закрепляет официальные пакеты и не
исправляет их файлы. Обновление Podkop/sing-box может сделать manifest несовместимым:
сначала проверяйте новую комбинацию на отдельном стенде. Не заявлена совместимость
с последующими версиями. Обновляйте расширение проверенным APK через тот же `apk add --allow-untrusted /tmp/<APK>`
после проверки совместимости. Переустановка текущего пакета сохраняет приватное состояние.

Диагностика на роутере:

```sh
/usr/libexec/podkop-tools/task status
sha256sum -c /usr/share/podkop-tools/compat.sha256
sing-box version
logread -e podkop-tools
```

В issue укажите версии, публичный код ошибки и обезличенный status. Даже публичные
названия узлов могут быть личными — проверьте текст перед отправкой. При
`state_conflict`/`recovery_conflict` не удаляйте state и не выполняйте слепой rollback.
Одновременная внешняя правка MAIN во время apply не поддерживается; редакторы,
игнорирующие UCI flock, не сериализуются нативной блокировкой.

## Ограничения измерений

Throughput: defaults 4 МиБ/6 секунд, максимум 16 МиБ/15 секунд, один узел за задание,
не чаще раза в минуту. Учитываются фактически полученные байты, TTFB исключён;
минимальная выборка — 256 КиБ и 0,5 секунды. Тест расходует часть канала.
HTTP204 означает доступность контрольного endpoint; проверка Telegram Web не
доказывает работу MTProto, сообщений или звонков. UDP/Discord Voice не проверяются.
Публичные defaults DNS/health/speed/service перечислены в конфигурации; их работа
через ваш провайдер не гарантируется. Автономные тесты используют собственные endpoint.

## Тесты

```sh
python3 tools/prepare.py --lab
npm ci --ignore-scripts
python3 tests/run.py all
```

Нужны Docker, OpenSSL на host и свободный ресурс для второго sing-box. Стенд использует
отдельную internal Docker-сеть, NET_ADMIN/NET_RAW только в контейнере и собственные HTTPS/DNS/VLESS fixtures внутри namespace. Python и браузер используют
публичные образы, закреплённые digest. Host-порты не публикуются, VPN/proxy/firewall
рабочей станции не перенастраиваются. Уже существующие тестовые ресурсы не
переиспользуются. Контейнеры и сеть удаляются в `finally`. Python-driver использует
Docker socket для управления ресурсами стенда; запускайте тесты из доверенной копии.
Отдельные наборы: `unit`, `integration`, `recovery`, `rotation`, `ownership`, `readiness`, `browser`.
Docker использует host kernel: это проверка userspace, а не аппаратного dataplane,
Wi-Fi или перезагрузки роутера. Миграции старых схем проверяются синтетически;
обновление настоящих исторических APK r2/r3 не сертифицировано.

## Удаление

На роутере выполните `apk del luci-app-subscription-toolkit`. Собственные задания
cron/boot выключаются; Podkop и MAIN сохраняются. Настройки и `/etc/podkop-tools`
сохраняются намеренно. После удаления пакета, если данные больше не нужны, удалите
их отдельно: `/etc/config/podkop_tools`, `/etc/config/podkop_tools_subscription` и
`/etc/podkop-tools`. Это необратимо удалит подписку, состояние и recovery-копии;
не выполняйте очистку при незавершённой транзакции.
